# YT-DLP Studio

Графический интерфейс для [yt-dlp](https://github.com/yt-dlp/yt-dlp): всё то же, что умеет консольная версия,
но с понятными кнопками, очередью загрузок и живым прогрессом.

Приложение запускается у вас на компьютере: Python-бэкенд использует yt-dlp как библиотеку, а интерфейс
открывается в отдельном окне или во вкладке браузера — как вам удобнее. Никаких внешних серверов —
всё работает локально.

## Desktop-приложение для Windows

Готовая программа: обычный `.exe` без консоли и без установки Python.

- **Установка** — `YT-DLP-Studio-Setup-<версия>.exe`. Ставится для текущего пользователя (права
  администратора не нужны), создаёт ярлыки в меню «Пуск» и на рабочем столе, удаляется через
  «Приложения» Windows. Есть и portable-вариант — `.zip`, который достаточно распаковать.
- **Всё внутри**: yt-dlp, ffmpeg, deno (JavaScript-движок, без которого YouTube отдаёт не все форматы),
  curl_cffi для TikTok и окно на встроенном в Windows 10/11 движке Edge WebView2.
- **Одна копия**: повторный запуск просто выводит окно на передний план.
- **Закрытие во время загрузки** спрашивает подтверждение.
- **Размер и положение окна** запоминаются; заголовок окна подстраивается под тёмную или светлую тему.
- **Обновление yt-dlp** — кнопкой в Настройках: новая версия скачивается с PyPI в папку пользователя
  (с проверкой контрольной суммы) и подключается после перезапуска. Если обновление окажется
  повреждённым, приложение само вернётся к встроенной версии; вернуться можно и вручную —
  кнопка «Встроенный yt-dlp».
- **Журнал**: `%APPDATA%\yt-dlp-gui\logs\app.log` (кнопка «Журнал приложения» в Настройках).
  Настройки и история лежат там же и сохраняются при удалении программы.

### Где взять сборку

Сборку делает GitHub Actions (workflow «YT-DLP Studio desktop (Windows)») при каждом изменении в этой
ветке: вкладка **Actions** → последний запуск → раздел **Artifacts**: `YT-DLP-Studio-<версия>-Setup`
(установщик) или `YT-DLP-Studio-<версия>-portable`. Перед сборкой workflow прогоняет тесты, а после —
проверяет готовый `.exe`: самопроверку (yt-dlp, ffmpeg, deno, curl_cffi) и настоящий запуск окна с выходом.

Собрать самостоятельно на Windows: `desktop\build.bat` (нужен Python 3.10+; для установщика —
[Inno Setup 6](https://jrsoftware.org/isdl.php)). Результат появится в папке `dist`.

Из исходников desktop-режим запускается командой `python desktop.py` (на Windows можно `pythonw desktop.py` —
без консоли); нужен `pip install pywebview`.

> Сборки не подписаны цифровой подписью, поэтому при первом запуске Windows SmartScreen может показать
> предупреждение «Windows защитила ваш компьютер» — нажмите «Подробнее» → «Выполнить в любом случае».

## Запуск

Нужен **Python 3.10+** ([python.org](https://www.python.org/downloads/)) и, желательно, **ffmpeg**.

| Система | Как запустить |
|---|---|
| Windows | двойной клик по `run.bat` |
| macOS / Linux | `./run.sh` |

При первом запуске скрипт создаст окружение `.venv`, установит yt-dlp и спросит, как открывать приложение.

### Отдельное окно или браузер

| Способ | Что сделать |
|---|---|
| При первом запуске | `run.bat` спросит: **1** — отдельное окно, **2** — вкладка браузера |
| Из консоли | `run.bat window` или `run.bat browser` (macOS/Linux: `./run.sh window`) |
| В приложении | кнопка с окошком в левом нижнем углу или Настройки → «Окно приложения» |

Для отдельного окна нужен [pywebview](https://pywebview.flowrl.com/) — скрипт и кнопка в приложении установят его сами
(около минуты). Выбор запоминается: дальше `run.bat` открывает приложение так же, как в прошлый раз.

- Windows: окно работает на встроенном в Windows 10/11 движке Edge WebView2.
- Linux: ставится `pywebview[qt]` (Qt WebEngine, ~150 МБ).
- Если окно открыть не удалось, приложение само откроется в браузере, а причина будет видна в Настройках.
- В режиме окна консоль `run.bat` остаётся открытой — её закрытие завершает приложение.

Вручную:

```bash
python -m pip install -r requirements.txt
python main.py            # как выбрано в настройках (по умолчанию — окно, если есть pywebview)
python main.py --window   # отдельное окно (и запомнить выбор)
python main.py --browser  # вкладка браузера (и запомнить выбор)
```

### ffmpeg

Без ffmpeg не получится склеить видео 1080p+ со звуком, извлечь MP3, встроить обложку, субтитры или главы.

- Windows: `winget install ffmpeg` — или положите `ffmpeg.exe` в папку `bin` рядом с приложением
- macOS: `brew install ffmpeg`
- Linux: `sudo apt install ffmpeg`

Статус ffmpeg виден в левом нижнем углу приложения.

### TikTok

TikTok отдаёт видео только «настоящему браузеру», поэтому yt-dlp нужна библиотека **curl_cffi**
(имитация браузера). Она уже есть в `requirements.txt`: `run.bat` / `run.sh` доустановят её при следующем запуске.
Если нет — в приложении: раздел «TikTok» или Настройки → «Установить curl_cffi», затем «Перезапустить».

- подходят ссылки `tiktok.com/@автор/video/…`, короткие `vm.tiktok.com/…`, `vt.tiktok.com/…`, мобильные `m.tiktok.com/…`;
- ссылка на профиль `tiktok.com/@автор` открывается как плейлист;
- по умолчанию выбирается кодек H.264 — HEVC-файлы из TikTok не открываются в стандартном плеере Windows;
- длинные описания обрезаются в имени файла (настройка «Макс. длина названия»);
- приватные ролики — через «Cookies из браузера»; из фото-каруселей yt-dlp скачивает только музыку и обложку.

## Возможности

**Загрузка**
- анализ ссылки: превью, автор, просмотры, длительность, таблица всех форматов;
- режимы «Видео» (качество от 360p до 4K, контейнер MP4/MKV/WEBM, кодек H.264/VP9/AV1, 60 fps),
  «Только аудио» (MP3, M4A, OPUS, FLAC, WAV, AAC, выбор битрейта) и «Свой формат» (`-f`/`-S`);
- выбор конкретных потоков кликом в таблице форматов — видео + аудио собираются в формат автоматически;
- плейлисты и каналы: список видео с галочками, каждое видео — отдельной задачей или одной задачей;
- пакетный режим: много ссылок сразу; перетаскивание ссылок в окно; вставка Ctrl+V в любом месте.

**Настройки загрузки** (запоминаются между запусками)
- папка и шаблон имени файла с подсказками, подпапки и нумерация для плейлистов, архив загрузок;
- субтитры: языки, автосубтитры, встраивание, конвертация в SRT/VTT/ASS;
- обложка, метаданные, главы, разделение по главам, описание, info.json;
- SponsorBlock: отметить или вырезать рекламу, выбор категорий;
- скачивание фрагмента по времени (или клик по главе);
- cookies из браузера или cookies.txt, прокси, ограничение скорости, повторы, параллельные фрагменты,
  обход геоблокировки, имитация браузера;
- любые дополнительные аргументы yt-dlp и, по желанию, ваш `yt-dlp.conf`.

Внизу страницы всегда видна **точная команда yt-dlp**, которая будет выполнена, — её можно скопировать
и запустить в консоли. Ошибка в параметрах подсвечивается сразу.

**Очередь и история**
- параллельные загрузки (1–8), прогресс, скорость, оставшееся время, этапы обработки;
- пауза / продолжение (докачка), отмена, повтор, журнал каждой задачи;
- история с поиском: открыть файл, показать в папке, скачать снова;
- уведомления о завершении, отслеживание ссылок в буфере обмена;
- обновление yt-dlp одной кнопкой; тёмная, светлая и системная темы, шесть акцентных палитр.

## Устройство

```
main.py              запуск: локальный сервер + окно/браузер
backend/options.py   настройки интерфейса → аргументы командной строки yt-dlp
backend/manager.py   очередь, потоки загрузки, прогресс, получение информации о видео
backend/server.py    HTTP API и раздача интерфейса
backend/storage.py   настройки и история (JSON в папке настроек пользователя)
backend/window.py    отдельное окно (pywebview) вместо вкладки браузера
backend/runtime.py   обновление yt-dlp в собранном приложении (без pip)
desktop.py           запуск desktop-приложения: окно, одна копия, журнал, самопроверка
desktop/             сборка для Windows: PyInstaller, Inno Setup, загрузка ffmpeg и deno
web/                 интерфейс: index.html, app.css, app.js
tests/               python -m unittest discover -s tests
```

Интерфейс собирает те же аргументы, что вы бы набрали в консоли, и передаёт их парсеру самого yt-dlp,
поэтому поведение совпадает с консольной версией один в один.

Сервер слушает только `127.0.0.1`, а все запросы к API требуют случайного токена, который выдаётся при
запуске, — другие сайты в браузере не могут управлять приложением.

Настройки и история хранятся в `%APPDATA%\yt-dlp-gui` (Windows), `~/Library/Application Support/yt-dlp-gui`
(macOS) или `~/.config/yt-dlp-gui` (Linux).
